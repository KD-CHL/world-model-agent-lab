# 研究问题与主线

当前工程目标：在任务场景明确前，打通 API Agent、机器人能力校验、动作条件预测规划、ROS 2 执行、MuJoCo 状态反馈的可替换闭环。论文假设尚未确定，未做外部新颖性检索。

| 路线 | 数据/目标 | 部分可观测性 | 成本与执行 | 接触操作及复现边界 |
|---|---|---|---|---|
| TD-MPC2（文献比较） | 仿真交互、奖励、技能 ID | 初期明确采用状态观测；视觉需历史/表征扩展 | 模型与价值联合训练，每控制周期有规划成本 | 接触转移需覆盖；先复现少量技能，不承诺论文水平 |
| Dreamer/DayDreamer | 序列、奖励、想象 actor–critic | RSSM 表达历史信念 | 训练含想象轨迹；执行 actor，无逐步 MPC 要求 | 可作后续替代；初期不并行复现 |
| DINO-WM | 离线动作图像轨迹、目标图像 | 历史特征输入 | 冻结视觉编码器，训练转移，执行优化动作 | 视觉目标需独立获取；预训练资源须披露 |

当前软件以 joint_goal 作为唯一内置目标，使用 DynamicsModel 注入预测关节状态，基于滚动候选规划输出一个动作。它是通信和插件接口，不是已训练模型或完成算法复现。上表只用于路线背景，未来方法需以独立实现、原始来源记录及实验确定。

任务场景和机器人资产尚未确定。interface_probe.xml 只有一个受限旋转关节，仅供接口验证；机械臂/Go2/G1 模板需填写实际 MJCF 资产和映射。末端 IK、夹爪技能和双足/四足运动控制仍需与后续任务一起设计。

未来世界模型必须预测动作条件的未来状态或任务相关表征，并由规划器使用这些预测选择动作。当前 DynamicsModel 契约用关节状态做最小探针；真实操作任务需要包含机器人状态、目标物状态、接触/场景观测的统一模型输入输出及相应数据训练代码。

当前 prediction report 把不确定性标记为 unavailable；没有训练模型或校准器时不能输出成功概率。未来可在收集与划分独立数据后选择不确定性估计和校准方案。

API 只返回目标 JSON，不能产生任意代码或直接下发 actuator 命令。命令经过 robot profile 和模型预测规划器校验，执行后以新状态闭环。大模型输出的目标仍须经过关节限位和任务合法性校验；它自身的回复不能证明任务成功。
