# 规划层世界模型：开源实现筛选

检索日期：2026-09-23。这里的“规划层”指在执行前用动作条件预测比较候选动作序列，并在获得新观测后重新规划。以下是方法和复现实验的参考，不代表这些仓库能直接驱动本项目的机械臂、Go2 或 G1。项目源码继续按功能命名，保留文献归属，不复制第三方代码并仅替换名称。

## 与本项目的接入顺序

1. **先让状态规划闭环可比较。** 保持现有 `Observation → PredictionReport → ActionCommand → ExecutionFeedback` 语义，统一候选动作数、预测步长、控制周期和仿真交互预算。先在明确的机械臂任务上，比较现有低维模型规划、无模型控制和模块化动力学模型规划。
2. **再研究高层 Agent 的收益。** 由 Agent 提供受约束的目标/技能候选；规划器对每个候选做动作 rollout，返回预测目标、分数、误差估计、模型版本和有效时间。Agent 只消费报告，不把模型的低层预测直接当成技能成功概率。执行后比较预测与实际状态，再决定继续、重规划或恢复。
3. **随后做视觉支线。** 固定相机、目标图像来源和动作接口后，复现视觉特征规划。视觉模型预测质量、候选排序和闭环成功率分别报告。若用语言目标，需要单独评估语言到目标表示的映射。
4. **最后扩展 Go2/G1。** 每个本体都要明确观测、动作、控制器与任务判据。Go2 的步态稳定和 G1 的平衡/全身控制不能由现有单关节探针或操作检查点推断得到。ROS 2 消息契约可以共享，动力学模型及安全回退通常需要按本体训练和验证。

## 不列为本次规划器主线的项目

- [DreamerV3](https://github.com/danijar/dreamerv3) 在学习模型中训练 actor–critic，执行时主要由策略出动作；适合作为世界模型策略学习对照，不能描述成每一步在线搜索候选动作。
- [UnifoLM-WMA](https://github.com/unitreerobotics/unifolm-world-model-action) 提供图像、状态与语言相关的动作生成及交互生成路线，更适合作为本项目第二数据源/动作策略支线。若要当规划器使用，仍需明确候选生成、统一评分、预测有效性与闭环重规划接口。

## 复现前的检查点

- 固定官方仓库提交、许可证、Python/PyTorch/MuJoCo 及 GPU 条件；本文仅按公开仓库说明筛选，尚未在本项目 Ubuntu 环境运行这些仓库。
- 对机械臂选择一个共享场景中的可重复任务，记录训练/验证/测试回合划分，避免相邻帧泄漏。
- 先测候选排序能力、多步预测误差、闭环成功率与规划延迟，再决定是否升级模型规模。
- 单独记录仿真交互步数、模型内部想象步数、预训练数据和计算资源；不得把借鉴方法的论文结果写成本文已验证结果。
