## 扰动与恢复分母

`pulse` 实际在 hold_A 第二个零动作周期注入 +.5 N·m/.2 s，随后恢复原外力。
外力已注入，但 hold_A 条件未失效、恢复未触发；后续2次恢复均来自 reach_B 停滞。
因此不能报告“扰动恢复成功率”，分母为0。配置里要求扰动，不代表已注入；
只有 disturbance.injected 和 record 可以证明注入，recovery_triggered 只计 hold_A。
recoveries_succeeded 只计实测条件重建，单纯重新规划不计成功。
确定性夹具测试验证了保持失效时R1只修复当前节点，不回滚已完成节点；
其通过不替代真实外力条件下的恢复验收。

## 设计修正与审计边界

重置后的实测肩/肘约 [.32358,.91761]，与起始命令 [.35,.87] 的误差约 .05445 rad。
原启动预检误用目标成功阈值，导致任何任务尚未执行就停止。现预检只检查命令
起点≤.015 rad以及实测实验包络；节点成功阈值未改，也不宣称启动时已稳定。
该修正由真实诊断及失败测试支持，并同步到设计规格。

原有 Agent 完整回执契约不变，新运行时独立记录部分执行。控制器执行后抛异常时
只额外独立观测一次，保留可确认的连续实际进度；未知实际总数标为 null并锁止，
禁止重新发动作。重复任务的预测文件使用决策UUID，不覆盖上次证据；A0固定程序
按与运行时相同的依赖调度顺序冻结，不依赖配置数组恰好已排序。
已执行物理周期由本地session的episode/step计数确认，独立于RGB成功接收数；
无法确认物理计数时明确保留未知标记。收到的故障前缀作为RGB/状态/残差工件
保存并标记 valid_for_history=false，不进入正常模型历史或节点完成验证。

客户端内置浏览器验收：五节点表/预算/恢复计数显示正常；切换既有实验后任务图
清空为“未记录”，没有混入上一个任务节点；捕获的控制台错误/警告列表为空。
技能指定的 agent-browser 命令不可用，采用内置浏览器，没有安装其他环境。
本次未验证桌面交互窗口全过程；无窗口真实物理测试及客户端历史记录已验证。
