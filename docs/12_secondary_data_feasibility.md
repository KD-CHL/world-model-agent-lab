# 视觉动作模型支线：实现、训练与第二数据源可行性

结论：**预训练权重推理可行性较高；特定机器人/任务的微调有条件可行；从零训练完整视频世界模型目前不能列为本项目必达里程碑。** 本结论是接口与资源约束下的实施判断，不是本项目已运行参考模型或取得论文增益的报告。世界模型规划与 MuJoCo 闭环仍为主线，见[主线设计](11_planning_world_model_pipeline.md)。

## 证据与约束

参考仓库的 [README](https://github.com/unitreerobotics/unifolm-world-model-action#readme) 发布了训练、推理、部署脚本和 Base/Dual 检查点，并给出视频模型预训练、下游 decision-making 与 simulation 两种后训练路径。训练要求图像、机器人状态、动作和语言描述配套；说明中的状态/动作默认最大维数为 16，超过需改配置，示例训练只用主视角图像。其 [部署客户端](https://github.com/unitreerobotics/unifolm-world-model-action/blob/main/unitree_deploy/scripts/robot_client.py) 使用具体 G1/Z1 配置、相机键和动作编码。这不证明任意机械臂或 Go2 权重可以直接运行。

官方 [Base 模型页](https://huggingface.co/unitreerobotics/UnifoLM-WMA-0-Base)要求接受访问条件。模型卡正文声明 CC BY-NC-SA 4.0，但页面元数据另显示 Apache-2.0；[Dual 模型页](https://huggingface.co/unitreerobotics/UnifoLM-WMA-0-Dual)也有这类冲突，[代码仓库许可证](https://github.com/unitreerobotics/unifolm-world-model-action/blob/main/LICENSE)为 CC BY-NC-SA 4.0。下载、改造和论文共享前需逐项核对代码、权重、数据各自适用的许可证及访问条件；本文不以页面标签替代许可判断。

当前项目仅实现 [动作服务 HTTP 客户端](../src/wmal/models/action_service.py)，并用假服务验证协议。没有参考模型权重、GPU 推理环境、ROS 图像 topic、相机标定或目标机器人动作映射。训练耗时、显存和吞吐尚无本机实测，不填入猜测数值。

## 第二数据源的严格定义

| 类型 | 产生方式 | 可用于 | 论文中应如何标记 |
|---|---|---|---|
| A：MuJoCo 交互 | 控制器或规划器驱动物理引擎，记录执行前后状态 | 动力学训练、控制评估 | `mujoco_interaction`，计入仿真交互步数 |
| B1：外部示范 | 合法获取的 G1/Z1 等原始示范轨迹 | 预训练/微调，或单列跨域测试 | `external_demonstration`，标原始数据集、机器人、许可、episode |
| B2：模型生成 | 条件输入产生的预测视频/状态片段，未经 MuJoCo 重放 | 数据增强假设或视觉预测质量研究 | `model_generated`，标源模型、检查点、提示与父轨迹；不作环境真值 |
| A2：模型引导的 MuJoCo | 动作服务提议动作，映射后由 MuJoCo 执行 | 策略对照、采样效率比较 | `model_guided_mujoco`，仍计入 A 的仿真交互，另记模型调用 |

论文若称“第二数据源”，最明确的是 **B1 外部示范**，或经严格标识的 **B2 模型生成数据**。动作服务只返回动作提议，它本身不产生独立状态真值；A2 仍依赖同一 MuJoCo 物理引擎。任何 B2 数据都须保留父数据和模型版本，不能与 A 的后验观测混为同一来源，也不能用于测试集真值。

## 推荐的实施顺序

1. **锁定一个机器人和任务。** 初期优先选择参考权重、训练示范、相机视角和 MuJoCo 模型都能对齐的 G1/Z1 操作任务。Go2 暂作接口预留；其任务、动作空间与现成示例差异需要先证明可映射。记录 `state_order`、`action_order`、单位、控制频率、夹爪编码、相机外参、语言标签与归一化统计。
2. **先复现单次推理。** 在 Ubuntu GPU 主机上使用上游独立环境与固定权重，仅发送一组公开示例，量测显存、初始化时间、p50/p95 推理延迟、返回动作形状。不要先把上游代码拷入本项目；本项目客户端经 HTTP 接口调用。服务重试策略、模型版本和错误码由本项目外层记录。
3. **接入 MuJoCo 图像和动作。** ROS 2 状态与图像按 episode/step/sim_time 对齐；重置清空历史；每个动作维度的语义显式配置。先取动作 chunk 首步，验证限位、速度和受控停止，再做短 chunk。两端步频若不同，要定义保持/重采样规则，不能直接把 16 步当 16 个 MuJoCo 物理积分步。
4. **做小规模微调试验。** 只用训练 episode，先验证数据转换、加载预训练权重、少量更新、恢复训练和冻结验证指标。记录真实 GPU 峰值、每步时长和数据吞吐后估算全量成本；GPU/驱动/版本由目标机器实测锁定。视觉模型若只作策略基线，可只训练 decision-making 分支；若要 B2 生成预测视频，必须验证 simulation 分支的输入与输出链路。
5. **纳入论文对照。** 固定场景和执行控制器，比较主线规划器、视觉动作服务及直接控制；如果比较“加入第二数据源”带来的收益，则固定模型结构、优化预算和 MuJoCo 交互预算，并分别报告外部示范量、模型生成量和模型调用计算。按来源与场景/episode 划分数据，检查上游预训练集与测试集是否重叠。

## 可行性门槛与收缩

| 门槛 | 通过条件 | 未通过时 |
|---|---|---|
| 权重与许可 | 取得可用检查点、确认用途与共享边界 | 仅保留接口设计；不用该权重生成论文数据 |
| 观测对齐 | 同步图像/关节历史、状态维数与归一化来源可核查 | 先做离线外部示范分析，不接机器人执行 |
| 动作对齐 | 每维动作可解释且通过限位/单步控制测试 | 只将服务输出作为离线提议，不驱动 MuJoCo |
| 训练资源 | 单批次前/反向、检查点和少量更新实测通过 | 使用冻结预训练权重，或只做主线状态模型 |
| 数据有效性 | 同任务、同观测、同预算下有预先定义的指标和独立测试集 | 标记为探索性结果，不写成性能提升证据 |

此支线的关键假设是：外部示范或模型生成数据是否改善主线规划器的数据效率，或视觉动作服务是否提供互补的候选动作。两者要分别实验，不能因为模型生成了看似合理的视频，就推断机器人任务成功或世界模型规划更好。
