## 1. 研究意图与范围

主线是“预测可信度辅助机器人 Agent 规划”：世界模型预测动作后果，Agent 维护
任务状态、组织候选技能、选择执行长度，固定低层控制器执行并返回真实反馈。
本次优先修复 Agent 的任务组织与恢复限制，不更换或训练世界模型，不同时训练
语言模型、VLA、行走策略或记忆模块。仅使用本项目 `wmal` 环境。

用户确认以现有固定底座 G1 两关节环境验证多阶段任务与失败恢复。本规格将其
限定为：到达 A、保持 A、到达 B、保持 B、返回起始目标。成功必须由完整的真实
执行证据确认；不存在合成成功、预测代替反馈或故障后盲目重试。

新增能力是任务图运行时、技能契约、独立验证、有限恢复、逐步执行检查及可回放
证据。第一阶段不实现抓取、装袋、折叠、移动操作、真机控制、跨场景泛化、在线
权重更新、检索增强、长时潜状态缓存或开放式语言任务分解。导航与 ROS 迁移是
后续工作；不以本次本机视觉实验替代对应验收。

## 2. 现状与设计选择

现有代码依据：

- `src/wmal/agents/predictive_skill_agent.py`：顺序目标向量，A0–A3，真实历史，
  校准前缀、不可篡改执行回执、失败锁止。任务推进主要按目标向量距离判断。
- `src/wmal/skills/registry.py`、`executor.py`：已有技能注册、前置条件、独立成功
  检查，但视觉候选规划尚未完整通过这一边界。
- `src/wmal/envs/visual_workcell.py`：两维关节目标增量、四维实测/命令状态；
  每次动作推进物理时间，可返回每步观测；异常会锁止，需要显式 reset。
- `scripts/visual_skill_agent.py`：有限候选、waypoints、JSONL 与 RGB 工件、
  持续查看窗口。它不支持保持节点语义及分类恢复。
- `src/wmal/models/horizon_calibration.py`：冻结的 episode 级、逐预测长度误差界；
  不是成功概率或安全保证。

三种路线：LLM 中心调度、在想象中训练策略、显式任务图与固定技能调度。采用第三种，
因为语言层与控制器保持不变，任务组织、模型评估和可信度作用可以分开测量。
本规格不把任务图、模型集成或这些已有机制的组合本身声称为新颖算法。

## 3. 组件与职责

```text
结构化任务规格
      ↓
任务管理器 → 技能契约/候选生成 → 世界模型适配器 → A0–A3 选择策略
      ↑                                              ↓
真实任务验证 ← 实际动作/逐步观测账本 ← 单一执行管理器
      ↓
推进节点 / 有限恢复 / 锁止或终止
```

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| TaskGraph/TaskState | 依赖、节点状态、完成事件、预算 | 发送动作、修改物理状态 |
| SkillContract/CandidateProvider | 参数、能力、前置条件、动作展开 | 宣称技能已成功 |
| WorldModelAdapter | 同一真实历史上的候选预测、语义/版本检查 | 输入未来真实观测、任意跨步外推 |
| SelectionPolicy | A0–A3 候选评估、选定授权前缀 | 任务成功判定、直接执行 |
| ExecutionManager | 单次授权、逐步执行、预算扣减、部分回执 | 不明确结果的自动重试 |
| TaskVerifier/RecoveryPolicy | 真实判据、固定恢复规则 | 利用故障注入器隐藏标签、修改模型/校准 |

`TaskRuntime` 单线程驱动这些组件，只有执行管理器可以调用 session 的动作接口。
监控读取事件，不直接控制执行。没有并发候选修改共享历史或多个执行线程。

## 4. 数据与接口契约

### 4.1 任务图

`TaskGraph` 包含 schema、task_id、不可变节点列表和图内容哈希。每个节点包含
node_id、依赖 ID、技能与参数、完成规则、前置/持续条件、节点动作预算。
静态加载时拒绝重复 ID、未知依赖、环、未知技能、非法参数、无法验证的完成规则。
可执行节点按配置顺序稳定选择，第一阶段不进行复杂图搜索。

完成规则分为：

- `event`：已验证的一次到达事件，之后离开该位置不撤销事实。
- `maintained`：只在该节点或明确指定的依赖区间持续成立；失效则暂停受影响步骤。

保持 A 的条件只覆盖保持 A 节点，不延伸到前往 B；否则图会自相矛盾。
不在运行时修改原始 DAG。恢复是带次数上限的运行时分支，成功后返回被阻塞节点。

### 4.2 观测与任务状态

保持模型现有 `VisualObservation` 的 RGB/四维 state 和 episode/step 语义不变。
执行封装另外记录 sim_time_s、单调时钟接收时间及动作 ID，不把这些加入模型输入。
任务状态包含 graph_hash、active_node、节点状态、完成证据引用、当前观测版本、
候选摘要、最后反馈、失败类别、预算和恢复记录。实验内模型与校准版本固定。

节点状态：`pending / ready / running / blocked / succeeded / failed`。
任务状态：`ready / running / recovering / succeeded / failed / budget_exhausted /
needs_review / fault_latched / canceled`。只在没有待执行回执时推进任务节点。
新 episode 必须开启新任务与历史；旧完成事件不可跨 episode 复用。

### 4.3 技能契约

采用独立的研究技能契约，适配现有注册器；旧 `SkillSpec` 调用保持兼容。
第一阶段只有 `joint_reach` 与 `joint_hold`，底层均为现有目标增量伺服控制器。
契约声明参数模式、关节顺序、单位、前置条件、动作展开、最大时长、真实成功
检测器和可恢复失败集合。两者都必须提供结构化、可执行候选；不能只传技能名称。

`joint_reach` 从当前真实命令目标生成受限增量序列；每步绝对增量不超过 .06 rad，
累计命令目标始终在既有 TARGET_LOW/TARGET_HIGH 内。候选数与随机种子有上限。
候选配置沿用现有生成方法；新任务模式只修改目标绑定，不偷偷改变模型或控制器。

`joint_hold` 执行零目标增量，保留当前命令目标，每步真实推进一个控制周期。
若命令目标与保持目标的 L2 距离超过 .015 rad，前置条件失败，不能通过零增量
假称保持目标位置；该阈值与 reach 完成规则一致，不要求浮点精确相等。
恢复到保持目标使用 `joint_reach`，不能借保持技能发出未授权纠正动作。

### 4.4 世界模型结果

输出包含 ensemble 逐步状态/可选帧、模型版本、语义、有效长度、耗时与诊断。
校准层独立产生误差界。支持范围检查包含图像/动作/状态模式、场景、控制周期、
模型训练长度和已声明数值范围，不声称这是经过验证的分布外检测器。
语义不匹配直接拒绝；无预测事件头时事件字段为 unavailable，不生成成功概率。

每个候选使用同一真实历史快照，K=2 的历史规则继续生效，未来只有候选动作。
预测长度最多为检查点支持的 H，第一阶段 H≤4；长任务由多个短决策组成。
重复候选评估不推进历史，也不改变真实状态。

### 4.5 授权与真实回执

授权绑定 task/node/decision/episode/start_step、观测摘要、图/技能/模型/校准版本、
具体动作字节、允许前缀、有效期限。版本、观测或任务节点改变使授权失效。
只有一份待处理授权；不能通过公共 ndarray 内容或 shape/dtype 修改实际授权。

第一阶段执行适配器逐动作调用现有 `execute_actions(action[None])`，统一收集真实
trace，在控制周期边界检查是否继续。父授权长度≤H，不把逐步调用计为多个计划。
有限执行结果是 complete、cooperative_stop、fault、unknown。回执记录计划与实际
步数、全部可得真实 trace、停止原因；实际长度可以小于授权长度，但绝不能超过。

提前停止使用新的显式部分回执契约。旧 `PredictiveSkillAgent.record_feedback`
仍要求完整旧回执，不放宽其校验，也不把末端观测复制成漏失的中间帧。
新路径仅按实际执行长度对齐预测和校准界；同一动作只能计费和接收一次。

有序、完整真实 trace 才能更新正常历史与任务事实。已实际发生的动作先记入
执行账本；反馈验证失败不撤销物理动作或预算，而是记为未解析并锁止任务。
拒绝在未解析账本上继续正常规划，不伪造已执行零步。

## 5. 调度、可信度与恢复规则

运行循环：独立观测 → 验证节点/前置条件 → 生成候选 → 策略评估 → 单次授权 →
逐步执行/核对 → 提交反馈与历史 → 节点验证 → 推进或有限恢复。
预测与节点验证分离：候选得分不能提交完成事件。

第一阶段保留现有 A0–A3 的距离型选择与误差界惩罚，不同时引入新奖励网络或
复杂成本函数。将选择逻辑提取为共享内部组件，新旧入口使用相同策略，回归
锁定旧行为。通用任务成本、多分支搜索属于下一阶段设计，不藏入本次实验。

- A0：任务开始前冻结有限动作程序，不根据真实偏差纠正；仍执行统一约束和
  成功检测。预定程序结束却未满足真实判据，任务失败，不无条件执行后续节点。
- A1：按当前真实状态和控制器名义结果修正，无学习型世界模型查询。
- A2：学习型预测排序，执行长度固定为 min(H, 剩余节点/任务预算)。
- A3：相同候选与预测，按冻结误差界选择连续可信前缀，不能在不可信步之后恢复
  为可信前缀。明确记录拒绝原因，不把误差界叫安全概率。

取消、任务条件失效、预算和实测限幅等共同停止条件对所有基线一致。预测误差界
检查属于 A3 可信度机制，只在该机制启用时触发，不偷偷加入 A2 或 A1。保持节点
的候选动作全为零，末尾不足 H 个采样时允许预算截短，不再强行生成不同关节动作。

恢复器只读取真实观测、残差和检测结果：

| 原因 | 动作 | 自动恢复边界 |
| --- | --- | --- |
| 保持前置/持续条件失效 | 阻塞当前保持节点，有限 reach 恢复目标，再重新计保持窗口 | 已确认全部执行结果、session 未锁止 |
| 执行有回执但持续无进展 | 在既有候选集合中换候选/重规划 | 不改变目标、限幅或总预算 |
| 预测超出冻结误差界 | 当前周期结束后协作停止，获取当前真实状态再评估 | 不自动重校准或改模型；仍须满足 A3 选择条件 |
| 没有可信前缀 | 有界重新评估或已许可信息技能；本阶段没有相机运动信息技能 | 同一状态重复读取不能算新增证据；预算用尽 needs_review |
| 漏帧、超时导致执行量不明确、重复/跨 episode 回执 | 终止授权并锁止 | 不重试；需显式重置后开启新任务 |
| 控制器异常、非有限状态、session 故障 | 保留物理 session 锁止 | 不使用恢复器绕过 reset |

预测失配是诊断信号，不被宣称为已识别故障根因。协作停止不调用异常锁止的
`abort`；控制器异常仍沿用现有锁止。恢复后不重做已成立的到达事件，只重建
当前所需持续条件。恢复动作和等待动作都计入节点及任务动作预算。

默认配置：总动作预算 80、每节点预算 24、总决策预算 120、任务恢复次数 4、
单节点恢复次数 2、连续无效观测/拒绝预算 3；均为整数且必须有限。无进展定义
为最近 3 个已确认 reach 动作的实测目标距离未减少至少 .005 rad，仅在当前
节点内计算，不用它判定 hold 失败。模型推理授权前超时默认 5 秒；执行超时
默认单动作 max(2 秒, 5×period_s)。本机同步物理步的期限在返回时核对，不承诺
抢占一个正在运行的底层调用；已返回且完整的 trace 仍按真实步数入账，然后停止。
未返回或缺少完整执行量才记 unknown，并锁止任务与 session，不并发发出下一动作。
阈值是开发初始值，必须写入 manifest；正式比较开始后固定，不在线自适应。

## 6. 首个验收任务

保持关节顺序：left_shoulder_pitch_joint、left_elbow_joint。
模型状态顺序仍为两实测关节加两命令目标。周期从检查点读取，现有数据为 .2 秒。
启动前要求当前 session 与检查点的场景、相机、分辨率、周期和动作语义完全匹配。

默认 reset 命令目标 [.35, .87] rad；任务规格存储这一显式起点，不在运行中替换。
A=[.43, .95]、B=[.27, .79]，均在现有包络内。启动要求命令目标与起点 L2≤.015
rad，实测关节在命令包络向外 .15 rad 的实验范围内；不宣称初始姿态已到达或已
稳定。2026-10-03 实测表明既有 reset 的伺服瞬态误差约 .054 rad，不能把节点的
到达成功判据用于启动预检。后续 reach/hold 的成功阈值不变，不偷偷 reset。

```text
reach_A → hold_A → reach_B → hold_B → return_start
```

reach 完成要求实测关节与目标的 L2 距离≤.035 rad，且命令目标与目标的 L2
距离≤.015 rad；不以完整四维状态向量的一次匹配替代稳定保持。
hold 要求连续 3 个已执行、连续 step 的真实观测均满足同一判据，默认 .2 秒
周期即 .6 秒实际控制时间。首次进入节点的静态观测不计保持时长；任一步失配
清零连续计数并阻塞，恢复后从零重计。保持完成是已验证持续窗口事件，不要求
此位置在离开后仍成立。最后 return_start 也需 3 个零增量真实保持采样确认。

仿真保持判据只是局部关节误差条件，不声称保证全身稳定、无碰撞或真机安全。
本阶段不添加模型未训练的速度、接触或物体事件输出。

扰动与验收分层：

- 确定性测试环境：注入可恢复条件失效、无进展、部分正常停止、漏反馈、版本
  变化、取消等，确认恢复和锁止协议。只能称契约测试，不能称真实机器人成功。
- 真实 MuJoCo 干净场景：至少一个冻结现有学习型检查点运行全部五个节点并
  保存逐步 RGB/状态/预测证据。A3 无可信前缀就如实记录，不能换成解析预测器
  或放宽阈值来伪装完成。若未成功，功能验收报告明确保留未通过项。
- 真实 MuJoCo 受控扰动：测试专用、独立于 Agent 的物理线程钩子，对肩关节
  施加 +.5 N·m 外力矩，持续一个控制周期后清零；只在一次 hold_A 的首个动作
  后触发一次。配置/时间/实际状态均记录，禁止直接改 qpos 或伪造观测。
  测试限定为局部包络内实验，实测关节超出命令包络向外 .15 rad 时停止并锁止。
  扰动可能不足以造成失败，必须记录“不触发”，不能把它算作恢复成功。

扰动注入器不向 Agent 提供失败标签，Agent 只能看正常传感反馈。扰动属于条件
变化，原校准覆盖率需重新测量，不把本轮恢复结果解释为形式安全保证。

## 7. 工程落点与兼容性

建议聚焦的新增模块：agents/task_graph.py、task_state.py、task_runtime.py、
recovery.py；skills/research_contracts.py、task_verifier.py。预测策略提取为
agents/selection_policy.py，世界模型、真实历史和不可篡改回执逻辑尽量复用。
这些是实现目标，不是本规格提交已经创建的源码。

新增专用多阶段运行脚本与 JSON 任务配置。旧 visual_skill_agent.py、旧关节/
导航/API/ROS 命令、A0–A3 默认值和检查点格式不变；不直接批量迁移全部路径。
配置必须显式指定 checkpoint、calibration（A3 必需）、baseline、恢复开关、
候选种子、全部预算、scene 和 disturbance；无静默使用其他项目环境或模型。

运行产物复用 runs 下新/空目录、run_manifest.json、events.jsonl、task_*.json
和 prediction_*.npz；清单增加 graph/skill/policy/config 哈希、模型/校准哈希、
控制器说明、测试钩子声明和软件提交版本。禁止覆盖现有实验或把权重/数据提交 Git。

日志保留现有 task_started、plan、execution_started、feedback、agent_state、
task_result 事件，新增 node_state、predicate_result、recovery_started、
recovery_result、execution_stopped。事件含 task/node/decision/episode/step、
sim_time_s 与墙钟时间；候选逐项记录筛除理由、前缀、预测/误差界及选择结果。
真实账本是离线全量评估依据，监控保留窗口不能替代最终实验统计。

现有客户端增加任务节点、保持计数、剩余预算、恢复分支与部分执行状态投影；
不增加网页远程动作权限。已有日志仍可读取，缺失字段显示 unavailable。
任务运行期间不调用未入账的 session.idle，所有物理推进都是明确记录的动作。
任务结束只结束调度，不关闭用户已打开的 viewer/monitor。窗口 idle 不计 Agent
动作，终止任务的历史证据冻结，后续 idle 观测不能回填该任务结果。idle 后再次
启动任务必须显式 reset 并建立新 episode；本阶段不复用未记录 idle 的时序历史。

## 8. 实验变量与验收标准

第一阶段分别报告“工程正确性”和“模型策略效果”。所有基线共享任务、控制器、
成功规则、硬约束、总动作预算和扰动定义；A1–A3 共享候选配置。A0 是冻结
开环程序，不虚称与反馈型候选完全相同。模型检查点/历史条件/校准均冻结。

恢复作为独立 R0/R1 开关。R0 检出可恢复失败后停止；R1 在上述有限规则内恢复。
A0 仅允许 R0，拒绝 A0/R1，避免把反馈恢复称作开环基线；A1–A3 支持 R0/R1。
主 A0–A3 比较先固定 R0；恢复效应以相同基线下 R0/R1 成对比较，尤其 A2 与 A3。
不把恢复收益全部记入可信度贡献。所有共同停止检查保持一致。

工程验收要求：

1. 静态图验证、能力/语义拒绝、事件与持续条件区分、真实保持计时都有测试。
2. 保持失效不能推进；重建条件只返回受影响节点；旧到达事件不被伪造或重复提交。
3. 缺少 trace/错误 step/篡改或重复回执、未知部分执行必须锁止且不产生第二次动作。
4. 所有观测等待、拒绝、恢复、执行路径都有有限预算；保持/恢复计入真实步数。
5. 同历史候选隔离、预测不读取未来、部分正常停止按实际长度对齐并有测试。
6. A1 不调用学习模型；A0 不反馈纠正；A2/A3 候选与预测输入保持一致。
7. 旧完整测试回归通过；新规格测试、真实 MuJoCo 多阶段 smoke、监控投影和
   启动文档分别记录通过/失败/未执行。基准 206 项不是未来必然测试总数。
8. 工程失败报告不得被隐藏；学习型 smoke 没完成五节点就不宣称功能全验收。

效果报告包括任务成功、正确子目标数、错误推进次数、恢复触发/成功/未触发、
动作数、保持重置次数、拒绝次数、重规划、执行长度、规划耗时、误差界宽度与
逐预测长度实测覆盖率。报告完整 episode 分母，失败与超时同样保留；样本不足
不计算误导性恢复率。禁止以一次成功宣称普遍优于基线。

开发 smoke 可用少量固定种子；后续正式比较需独立冻结测试集及多个模型训练
种子，开发集阈值不能再随测试调节。本次不以已有反复查看的四个 episode 作为
新论文最终测试集，也不虚称已经完成正式消融或统计显著性检验。
