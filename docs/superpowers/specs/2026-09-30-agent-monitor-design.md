# Agent 实验监控客户端设计

## 目标与研究约束

构建一个本机运行的只读监控客户端，帮助研究者观察 Agent—世界模型—机器人仿真的完整闭环，并检查模型预测是否影响计划、真实执行结果是否与预测一致，以及偏差是否触发重规划。客户端是实验观测工具，不是论文核心方法，也不控制机器人、不更改 Agent 决策或实验参数。

首版必须支持 MuJoCo 实时画面和实验事件的同步展示，并能浏览已完成实验。项目目前有多种实验入口和事件 schema；缺少字段必须显示为“未记录/不适用”，不得推断或伪造可信度、成功概率、状态或预测结果。

## 方案与范围

采用本机浏览器仪表盘 + 轻量 Python 服务 + 实验进程内只读遥测发布端。服务默认仅绑定 loopback 地址，不连接云端、不上传实验数据。遥测通道分离：结构化事件沿用并兼容 `events.jsonl`；实时图像和仿真元数据由仿真所有者线程发布。通过 `run_id`、`episode_id`、`step_id` 和 `sim_time_s` 尽可能精确关联，缺少标识时明确显示未对齐。

首版覆盖 G1/固定工作台视觉 Agent 实验和可提供帧发布接口的 MuJoCo 实验；事件日志历史浏览可兼容其他采用 JSONL 事件格式的实验。无实时帧发布端的旧实验仍可查看事件、摘要及已保存的预测/结果图像，并显示实时画面不可用。暂不实现远程/多用户部署、客户端动作控制、实验配置编辑、云同步、长期数据库、视频剪辑导出和可编程插件市场。

## 功能规格

### 实时实验工作区

- 显示连接状态、run 标识、实验类型、实验/回合状态、当前仿真时间与步号、帧更新时间和帧延迟。
- 展示 MuJoCo 环境的实时 RGB 帧；选择已配置相机（实验源明确支持时）；画面停止更新、源退出或 run 更换时给出明确状态。
- 展示任务目标、已完成/当前/待执行子目标、Agent 状态、循环预算、候选技能、所选技能/动作段及可用的选择理由。
- 展示世界模型版本、预测跨度、预测结果、可用的不确定性/校准区间、规划耗时；只按日志语义呈现。未校准的 ensemble spread 不显示为失败概率。
- 将可用的预测状态/图像与执行后的真实观测并排或叠加比较，并展示残差、超界/不匹配及触发的反馈修正/重规划事件。
- 展示机器人/环境状态、关节/基座关键状态及接触/安全停止信息（事件或帧元数据有记录时）。

### 事件时间线与诊断

- 按时间顺序展示任务开始、目标解析、候选生成/计划、世界模型预测、命令发送/确认、执行、反馈、预测残差、重规划、失败/安全停止和任务结束等事件。
- 支持按事件类型、回合、步骤过滤；点击事件定位关联帧和预测/执行对照（有对应数据时）。
- 实时 tail JSONL 时容忍最后一行尚未写完；跳过并报告损坏记录，不崩溃，不修改源日志。日志轮转/替换后重新识别文件并显示来源变化。
- 对重复、缺失或乱序事件保留原始时间戳和记录顺序，不构造缺失决策。任务无终态事件时标记 incomplete。

### 实验列表、历史回放与比较

- 扫描用户指定的 runs 根目录，列出实验目录、日志、manifest、任务结果、训练报告和预测图像等已知产物；受控访问指定根目录内的文件，不允许任意路径读取。
- 展示 run manifest 中可用的 commit、dirty 标记、实验 variant、配置/模型/校准版本、数据来源、随机种子、运行平台及 MuJoCo 版本。
- 历史回放按事件/步骤浏览现有逐步图像或预测 NPZ；无逐步观测图像时不可声称可完整视频回放。
- 展示描述性指标：任务成功/失败/未完成计数、耗时、循环/重规划数、计划时延、可用预测残差、仿真/模型步数等；单位、样本数、来源清晰标注，不把回合当独立训练种子进行推断。
- 支持同一结果视图对比不同 run 的已记录指标；不在客户端执行统计显著性检验或生成研究结论。

### 可观测性与数据留存

- 原始事件日志仍为实验证据的权威来源；客户端只读。新增的监控元数据若单独落盘，放置于 run 的独立 monitor 子目录，使用临时文件原子更新，并注明 schema 版本。
- 实时帧默认只保留有界的内存最新帧/短环形缓冲区，不无限写视频、不显著增加仿真存储；历史持久化帧仅复用实验本来保存的图像证据。
- UI 对事件和图像严格执行尺寸/类型/有限数值校验；事件文本按纯文本呈现；不读取 `.env`、环境密钥或任意外部 URL。
- 本机 HTTP 服务只绑定 `127.0.0.1`；禁止启动时自动暴露到局域网。所有文件访问限制在用户配置的 runs 根目录内。

## 系统架构与接口边界

1. **遥测数据契约**：版本化 `RunDescriptor`、`SimFrame` 和标准化事件视图。`SimFrame` 含 run/episode/step、仿真时间、wall-clock 时间、相机名和编码图像；事件保留源 schema/event/payload，并提供可选标准字段而不丢弃原始数据。
2. **仿真帧发布端**：实验进程创建帧采集/发布对象；只有执行仿真或本来采集观察帧的线程可调用发布。发布实现复制 RGB 数据后交给线程安全、有界的 latest-frame buffer；Web 服务不持有 MuJoCo model/data/viewer 引用。帧采集频率、尺寸可配置且有限值校验；关闭客户端或发布端不改变物理步进和动作序列。
3. **事件源**：只读、增量读取 JSONL；每个 run 独立游标/错误；检测新增数据、截断和 inode/路径替换。标准化层支持顶层字段形式和 `{wall_time_utc,event,payload}` 包裹形式，并保留原始内容。
4. **本地服务**：提供只读 HTTP 页面/API、实时事件订阅和最新帧接口。管理 run 选择、路径边界、心跳/过期检测和数据对齐；不承担推理、规划、执行或保存私密凭证。
5. **浏览器 UI**：实验选择器、实时监控工作区、预测/执行对照、事件时间线、历史结果页。客户端与仿真解耦；服务或 UI 重启不重启/暂停仿真。

通讯优先采用浏览器原生 HTTP + Server-Sent Events（事件流）与 JPEG 帧轮询/请求，不新增 WebSocket 复杂度。帧和事件接口均支持 run 标识与最近 step，客户端明确显示对齐误差/过期情况。若现有依赖或运行环境限制该实现，保留协议边界后再选择等价的轻量本机传输，不允许跨线程访问 MuJoCo 状态作为捷径。

## 错误处理与安全

- 遥测无消费者、慢消费者、缓冲区已满、渲染失败或客户端断开均不得阻塞仿真控制循环；采用覆盖旧帧的有界策略并计数丢帧。
- 仿真结束后保留最后一帧并显示 source stopped；事件服务继续支持历史浏览。发生 run 切换时清理旧的实时缓冲引用，不能将旧帧标成新回合。
- 事件 JSON 损坏、字段缺失、未知 schema、超大行/帧和不支持的 NPZ 结构均产生可诊断的 UI 状态，不造成任意代码执行或进程崩溃。
- 仅本机访问；不在界面显示 API key、环境变量、完整提示词或未经脱敏的外部响应。错误展示类型和安全摘要，不渲染 HTML。
- 客户端无命令、重置、暂停、恢复或参数修改路由；仿真控制权限仍由既有实验入口持有。

## 验收标准

1. 在现有 MuJoCo 视觉工作台 Agent 实验中启动监控器后，浏览器显示真实实时相机画面、任务事件与 Agent/模型状态，任务执行完成与否不依赖浏览器是否连接。
2. 一个计划/预测/执行/反馈周期内，UI 能按 run/episode/step 展示可获得的预测与实际观测、残差及重规划事件；无法对齐时给出缺失说明，不静默错配。
3. 新增事件能在运行中出现；不完整末行和日志追加不会使读取器崩溃或重复显示已消费记录。
4. 断开浏览器、停止服务、帧采集异常或帧缓冲拥塞不改变仿真动作/状态结果；队列内存有界。
5. 可选择并浏览至少一个已有 `runs/visual_*` 实验的事件、任务 JSON 和保存的预测 NPZ 图像；缺少历史帧时显示能力边界。
6. 路径越界、非 loopback 监听配置、畸形事件/图像、未知 run 等测试均被拒绝或安全降级；无控制类 API。
7. 单元测试验证数据契约、JSONL 增量读取、帧缓冲并发/背压、路径边界、服务接口和事件/帧对齐；集成测试使用 fake telemetry 和 MuJoCo 小场景。现有 Agent/仿真完整测试套件继续通过。

## 设计决策记录

- 选择只读浏览器客户端，而非原生桌面应用：易启动、可查看图表/图像，不绑定特定桌面 GUI 框架。
- 选择进程内帧发布 + 独立本机监控服务，而非服务线程直接渲染：遵守 MuJoCo 状态所有权，降低对仿真控制的干扰。
- 首版对接一个真实视觉工作台 Agent 路径，随后复用协议扩展 G1/其他入口；没有图像源的实验仍可在事件层被监控。
- 首版不要求新增数据库或完整视频录制：事件日志和现有预测工件已提供可复现证据，实时显示使用有界易失缓冲。
